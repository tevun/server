# Tevun ~ WIP

Tevun is a set of scripts intended to make life easier for developers and sysadmins in general.
It combines docker, docker compose and git to automate tasks such as uploading containers, configuring reverse proxy, configuring SSL, and more.
After setting up tevun on your server you can upload an environment that applies your development docker compose and configures a virtual host for your Let's Encrypt SSL-enabled domain quickly and simply.
Each created project generates a remote git that is already preconfigured to publish the application to the destination directory.
That way we can configure the scripts to publish our changes in our stage or production environments.

## Getting Started

### Requirements

Verify that your server has the following requirements:
- Git (`git --version`): git version +2.10.x
- Docker Engine (`docker -v`): version 20.10+ with the Compose plugin (`docker compose version`)

### Layout

After installation, the relevant paths on the server are:

```
/usr/share/tevun/
├── tevun.sh, commands/, samples/, ...   # source code
├── .docker/                             # container/runtime config
│   ├── docker-compose.yml.sample
│   ├── docker-compose.yml, .env, .key   # generated by `tevun setup`
│   ├── nginx-proxy/                     # nginx-proxy snippets and vhost defaults
│   └── ...                              # named volumes (certs, vhost, html, acme)
└── projects/                            # one subdir per project
```

The split keeps the source code and project files separate from the running container infrastructure: working in `projects/` cannot accidentally affect the proxy stack.

### Download

Access your server using ssh:
```
$ ssh root@<server>
```

Then clone the repository and create the symlink so the `tevun` command is available globally:
```
# git clone https://github.com/tevun/server.git /usr/share/tevun
# ln -s /usr/share/tevun/tevun.sh /usr/bin/tevun
```

### Setting up Tevun

#### Users and permissions

> If you already have a user with permission to run docker, skip this section.

It is important to avoid using `root` via SSH. We recommend creating a limited user, adding it to the `docker` and `sudo` groups, and using that account from then on.

You may use the `vps-bootstrap` scripts (separate repo) for a complete server bootstrap (zsh setup, sudoer configuration, etc.). Tevun also ships with two thin helpers that remain available:

```
# tevun user <name>     # creates the user and adds it to docker
# tevun ssh <name>      # configures sshd to allow the new user
```

These helpers are kept for compatibility but are not required by `tevun setup`.

#### Tevun setup

Run as root (or via `sudo`) so the script can write to `/usr/share/tevun` and create the docker network:

```
# sudo tevun setup
```

The setup will:
1. Configure git (user.name/email/default branch from local config or prompt)
2. Generate `.docker/.env` from the sample, prompting for `Host` and `SSH port` (defaults auto-detected)
3. Create `/usr/share/tevun/projects/` owned by your user
4. Symlink `/projects` → `/usr/share/tevun/projects` (shorter SSH URLs)
5. Generate `.docker/docker-compose.yml` from the sample
6. Create the `reverse-proxy` docker network (if missing)
7. Bring up the proxy stack with `docker compose up -d`

The proxy stack contains two containers:
- **nginx-proxy** (`nginxproxy/nginx-proxy:1.10`): reverse proxy that auto-discovers containers via the `VIRTUAL_HOST` env var
- **acme-companion** (`nginxproxy/acme-companion:2.6`): issues and renews Let's Encrypt certificates for containers that declare `LETSENCRYPT_HOST`

You can run `setup` non-interactively with `--quiet` to take all defaults.

### Using Tevun

`.docker/.env` controls runtime properties. Edit it with your favorite editor before/after setup.

#### Create a new project

```
$ tevun create <project> <template>
```

This adds a new project under `projects/`. `<template>` can be `php`, `html`, `laravel`, or `wordpress`.

Example:
```
$ tevun create site.com html
```

This creates `projects/site.com/`, initializes a bare git repo, configures `post-receive` for auto-deploy, and generates a `docker-compose.yml` for the project. The remote URL is printed at the end.

#### Destroy a project

```
$ tevun destroy <project>
```

Stops the project containers (`docker compose down`) and removes the project dir. Volumes are not erased automatically — be careful.

#### Other commands

```
$ tevun ps                    # show running containers
$ tevun ll                    # list project folders
$ tevun pull                  # pull new images for each project and restart
$ tevun lets-encrypt/renew    # force certificate renewal
$ tevun lets-encrypt/status   # show certificate status
```

### Configure in an existing project

To pull the `setup` branch of a freshly-created project remote into a local repo:

```
# add the remote to your repo
$ git remote add deploy ssh://<user>@<host>:<port>/projects/<project>/repo
# fetch the setup branch
$ git fetch deploy +refs/heads/setup:refs/remotes/deploy/setup
# get setup branch from remote
$ git branch --track setup refs/remotes/deploy/setup
# merge setup branch to your local branch
$ git merge --no-ff deploy/setup --allow-unrelated-histories
```
